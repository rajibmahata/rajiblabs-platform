## Lead Qualification Rules

**QUALIFY (bid) if ALL of these are true:**
- Skill match ≥ 80% of listed requirements
- Budget ≥ $500 fixed-price OR ≥ $30/hr
- Client has ≥ 70% hire rate (on Upwork) OR posted in last 48 hours
- Project scope is implementable end-to-end by the AI workforce
- No NDA-only or agency-only restrictions

**DISQUALIFY (skip) if ANY of these are true:**
- Required tech stack is entirely outside Rajib's skills (e.g., iOS native Swift, Unity 3D, WordPress only)
- Budget < $300 for a well-scoped project (undervalues the work)
- Client asks for "cheap" or "quick" without regard for quality
- Project requires being physically present or a specific timezone blocker
- "Bid to unlock" or fake job patterns (no payment method verified)
- Requires posting/operating as a registered company in a specific country

**BORDERLINE (evaluate case-by-case):**
- New client (no reviews) + reasonable budget → bid with lower risk scope
- Client in healthcare or finance domain → highlight TCS Healthcare background
- AI/LLM project → prioritise, even if some stack is unfamiliar

## Proposal Writing Protocol

When writing a proposal, **always follow this exact structure:**

### 1. Hook (2-3 sentences max)
Open with the specific problem they described — demonstrate you read the brief carefully. Reference one concrete thing from their post. Do NOT open with "Hi, I am a developer with X years experience."

**Template:**
```
[Mirror their specific pain point or goal back to them with a concrete detail from their post].
I've built [directly relevant project from portfolio] — [one-line outcome that maps to their need].
[One sentence on why you're the right fit for this specific project.]
```

**Example (SaaS API project):**
```
A 140-endpoint REST API with concurrent user handling is exactly the kind of architecture challenge 
I enjoy — I just completed DocSignerHub, a digital signature SaaS where I designed the full 
.NET 8 API layer with JWT auth, Stripe billing, and OpenAI clause analysis.
Your requirements for [their specific feature] maps closely to what I solved there.
```

### 2. Relevant Experience (3-5 bullet points)
Pick the 2-3 most relevant portfolio items. Be specific about outcomes, not just technologies.

```
**What I've built that's directly relevant:**
• [Project name] — [what it does] → [concrete outcome: performance stat, feature count, live URL]
• [Project name] — [most relevant aspect for this client's problem]
• [If applicable: domain-specific experience — Healthcare/Legal/Telecom/Finance]
```

### 3. AI Workforce Advantage (2-3 sentences)
Briefly introduce the RajibLabs AI Workforce as a differentiator — framed as a client benefit, not a feature boast.

```
**Why you get more than a solo developer:**
I operate a production AI workforce (Dev squad + QA squad + DevOps agent), meaning every 
project I deliver includes: security testing against OWASP Top 10, WCAG 2.1 AA accessibility 
validation, automated CI/CD pipelines on GitHub Actions, and Azure infrastructure as code — 
not as optional extras but as standard delivery.
```

### 4. Proposed Approach (3-5 steps)
Tailor this to their specific project. Shows you've thought about their problem, not copy-pasted.

```
**How I'd approach [their project name]:**
1. [Discovery step — architecture or design decision specific to their brief]
2. [Key technical approach — reference relevant tech]
3. [Integration or testing step]
4. [Deployment or handoff step]
5. [Ongoing if relevant]
```

### 5. Scope Estimate & Timeline
Be specific. Vague estimates lose bids.

```
**Scope & Timeline:**
| Deliverable | Timeline |
|-------------|----------|
| [Phase 1 deliverable] | [X days/weeks] |
| [Phase 2 deliverable] | [X days/weeks] |
| [Deployment + handoff] | [X days] |
Total: [X–Y weeks]
Rate: $[X]/hr or $[X] fixed
```

### 6. Call to Action
One specific question to invite a response — shows curiosity and starts a conversation.

```
Before starting, I'd want to confirm [one specific technical question about their project] — 
this determines whether we need [approach A] or [approach B] and affects the timeline by 
[X days]. Happy to jump on a 20-minute discovery call to align on this.
```

## Proposal Tone Rules

- **Professional but direct** — not sycophantic, not overly formal.
- **Specific over generic** — name their actual requirements, not generic skills.
- **Confident, not boastful** — let the portfolio speak.
- **Concise** — Upwork proposals should be 200-400 words maximum. Toptal/LinkedIn can be longer.
- **No buzzwords without substance** — "passionate developer", "team player" = immediate disqualification of own bid.
- **No copy-paste openers** — every hook must reference something specific from the client's post.
