## Goal
Create a single comprehensive **architecture + master implementation prompt document** (`proposals/rajiblabs-ai-backend-master-prompt.md`) that you can paste into any capable AI coding agent (OpenAI) to build the full RajibLabs automated platform. No application code is written now — the document is the deliverable.

## Key decisions (confirmed)
- **Stack:** Python FastAPI + SQLite (SQLModel/SQLAlchemy), JWT admin auth, Jinja2-served admin web panel (single admin: Rajib).
- **Replaces** `backend/RajibLabs.Api` as the site API (the plan will note parity with its existing public endpoints so the React frontend keeps working: `/api/projects`, `/api/profile`, `/api/contact`, `/api/health`, etc.).
- **AI:** OpenAI low-cost mini model only, for content management + chat.
- **Chat:** AI conversation grounded on site/portfolio content + structured lead capture (name, email, phone, description) stored in SQLite, shown in admin with notifications.

## Document contents (sections)
1. **Executive summary & product concept** — RajibLabs as a fully AI-automated portfolio/CMS platform.
2. **System architecture** — component diagram (FastAPI app, SQLite, GitHub sync agent, AI content agent, chat agent, admin panel, public API), data-flow descriptions.
3. **Complete data model** — SQLite tables: AdminUser, Notification, Lead (+ chat transcript), HomePageContent, Section, Skill, GitHubRepo (link + stored PAT ref), PortfolioProject (demo video URL, live URL, repo URL, screenshots, tech stack, AI-written description fields + `IsManualEdit` flag), SyncLog, AgentRun, Settings, Resume upload.
4. **Public API spec** — endpoints mirroring the current .NET API + new portfolio/chat endpoints, with request/response JSON examples.
5. **Admin API + web panel spec** — login/JWT, CRUD for every entity, notifications bell, lead inbox, repo token management, agent control (run now, schedule, review AI edits).
6. **GitHub integration & agentic system** — PAT usage, repo sync job; **daily-commit validator agent** that checks recent commits/README and updates site content; **content-writer background agent** that drafts/polishes project descriptions (manual edits never overwritten without approval).
7. **AI chat widget spec** — embed script, conversation flow, RAG-lite over DB content, lead extraction and storage, admin notification on new lead.
8. **Non-functional requirements** — security (token storage, CORS, rate limiting), cost control (mini model, caching, token budgets), error handling, logging.
9. **Config** — `.env` template (OPENAI_API_KEY, OPENAI_MODEL=gpt-4o-mini, GITHUB_TOKEN, JWT_SECRET, etc.) + `config.py` loading rules.
10. **Project scaffold** — exact folder structure, dependency list (`requirements.txt`), run instructions.
11. **QA agent instructions** — validation checklist the implementing agent must run against every feature (auth, CRUD, sync, chat, notifications).
12. **The master prompt itself** — a final self-contained "copy-paste" prompt block wrapping all of the above as direct instructions to the implementing AI agent.
